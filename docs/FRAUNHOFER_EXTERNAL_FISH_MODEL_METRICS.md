# Wave 14G — genuine external fish detector domain-transfer + tracking benchmark

This wave combines the original Oxford fish-specific trained
EfficientDet-D2 model from Wave13B, real ByteTrack, Fraunhofer HHI's
**actual crowded Sulawesi ricefish Video A JPEG pixels**, and the
unmodified official TrackEval HOTA/IDF1/CLEAR metric classes.

**This is a domain-shifted frozen-model run**: the detector was trained
on Oxford's Picasso triggerfish trials, NOT trained/fine-tuned on this
Fraunhofer ricefish experiment. Thresholds .25/.50/.70 are frozen in
the script and must not be adjusted after examining source labels.

## Exact external sources

Original high-density ricefish Video A source ZIP:
https://cvg.hhi.fraunhofer.de/FishTrackingData/video_a/mot_a.zip

- SHA256 `18c39619b1f84ea774f16fedfac5911d92de86ab7da4aa03cf365b9b4be58ceb`.
- Original 101 JPEG source image frame IDs 43,450–43,550.
- Original source `mot/gt/gt.txt` SHA256
  `b70a699b4e41cbec636e5f4b500482451d40ddad29fb387dc36dc0c6392021d3`.
- Source **9,214** fish boxes from **260** original IDs, not the
  source webpage's descriptive 256 fish IDs.
- Source GT IDs are **never provided to the detector nor ByteTrack**,
  only compared against independently generated model/tracker outputs.
- Source image 2448×2048 pixels, source timestamps/PTS **not
  independently available from the ZIP's images**. Local frame 1–101
  is mapped from the original source frame numbers without fabricating
  an FPS-to-time conversion.

Original fish-trained frozen Oxford EfficientDet weights:
https://github.com/ox-vgg/fish-tank-obstacles at source commit
`0d57a17148f750ed7c327ba5d36ce587d3b7dcfe`; all three
original weights/saved-model component Git blob hashes checked by
`check_frozen_model()`.

Official TrackEval reference:
https://github.com/JonathonLuiten/TrackEval
commit `12c8791b303e0a0b50f753af204249e622d0281a`.

## Actual complete pipeline

1. Verify original source ZIP and human-reviewed source GT SHA256.
   Verify every original JPEG name is an exact source frame index;
   require all 101 frames and 9,214 original rows. Validate
   source 260 distinct fish identity IDs.
2. Load the original frozen Oxford SavedModel and infer **all 101
   original ricefish source JPEGs**, with no tracker-generated
   position or GT identity provided as model input.
3. Preserve source frame provenance, hashes per image, and input
   spatial transform. Reject wrong source image dimensions and
   invalid model outputs. Original model high-confidence out-of-frame
   detections must count as detection false positives.
4. Recompute external-domain box TP/FP/FN at IoU .50 and the
   prespecified confidence .25/.50/.70 against original reference boxes.
   All 101 original frames are included, even no-fish frames.
5. Run Supervision ByteTrack 0.26.1 with the model-generated, possibly
   imperfect fish boxes and model scores, not reference GT.
6. Compute full official TrackEval HOTA/DetA/AssA/IDF1/MOTA/IDSW
   on source per-frame GT IDs versus newly generated ByteTrack
   outputs; export model/track CSV and source-verified JSON evidence.
7. CI uploads only derived model-track data and evidence, not the
   original potentially copyright-protected JPEGs or frozen weights.

## Limitations

**Source authenticity caution:** original Fraunhofer host has
incomplete HTTPS issuer chain, so the runner downloads with
`--insecure` only for scientific inspection. Exact ZIP SHA
matches the independently observed prior archive checksum, but
cannot alone authenticate the publication's download peer.

The dataset has semi-automatic annotation histories and its
identities have not been blinded-adjudicated for AquaTrajectories.
This qualifies a genuine cross-domain, model-based fish-tracking
benchmark if CI passes, not a universal animal-ID certification or
a manually audited blinded ground-truth corpus.
This is one 101-frame external video, no optimized adaptation,
limited generalization to other species/tanks.

Hardware multi-GoPro synchronization and source surveyed physical
underwater XYZ accuracy are outside this single-camera sequence.
True camera exposure time is **unknown**; the 30-fps ByteTrack
configuration is an explicit tracking-memory parameter assumption,
not measured original video timing.

Independent broader Level2 and biological/ACI acceptance remain
issues #46 and #51.
