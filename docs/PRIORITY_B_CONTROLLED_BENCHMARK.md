# Priority B — controlled real-video detection and identity benchmark

**Status:** implemented and CI-qualified as a **software evaluation contract**,
not as an empirical three-model comparison. Never transcribe invented fixture
scores into a publication table. Software code can pass while actual
idtracker.ai, SLEAP and trained YOLO source recordings remain missing.

## Existing real-video evidence (must not be relabelled as Priority B)

- [Wave 13E, Oxford video](https://github.com/stefanosbalaskas/AquaTrajectories/actions/runs/43287906771):
  genuine 149-frame Oxford fish-video inference with frozen source EfficientDet-D2
  and ByteTrack; original LISA reference **detection boxes** but no independent
  manually verified persistent fish identities. Not YOLO.
- [Wave 14G, Fraunhofer ricefish A](https://github.com/stefanosbalaskas/AquaTrajectories/actions/runs/43372413985):
  real 101 original JPEG frames, 9,214 reference boxes, 260 published
  fish IDs; frozen Oxford **EfficientDet-D2**, ByteTrack and official
  TrackEval. This is a domain-shifted source dataset and its identities
  may have been model-assisted.
- [Wave 14H, Fraunhofer ricefish A](https://github.com/stefanosbalaskas/AquaTrajectories/actions/runs/43393919168):
  same model-generated source boxes passed to ByteTrack vs a deterministic
  IoU/Hungarian tracker. It is a proper same-detector two-association experiment
  on one recording, **not** a three-model test, blinded expert certification,
  or a fish-specific fine-tuned YOLO experiment.
- Original Fraunhofer data **lack verified per-frame physical timestamps** in
  the downloaded 101-JPEG source. Do not fabricate speed in pixels/second
  from nominal FPS. Source annotations are not blinded-adjudicated.

## Study design and split requirements

Before any model inference, freeze **at least three recording-disjoint subsets**:
train, validation and final test, with source recording IDs, camera/tank fish
group, session and original video SHA-256. No animal group, source session
or video byte hash may overlap across partitions; the splitter refuses
duplication. External/public pretrained networks may have unreviewable
training histories; disclose this.

Keep the following workflows separate:

| Method | Training/selection | Actual test inference | Legitimate outputs |
|---|---|---|---|
| idtracker.ai 6 | identity learning on the **unlabelled test session itself**, openly labelled *transductive* | native video analysis, predicted per-frame centres and ID confidence | centres and fish ID, **not detection confidence**; no invented fish body boxes |
| SLEAP | source fish pose-model training/selection on train/validation, no test **reference labels** | SLEAP model predicts native instances/visible keypoints and tracks | pose-derived centre (proxy), native instance score when recorded; native boxes only if verified |
| YOLO + ByteTrack | source group-disjoint train, val-only checkpoint/threshold selection; original `best.pt` hash | actual pixel inference through PyAV and model-generated ByteTrack observations | real scored XYWH boxes, centres, camera-local ID and frame PTS |

idtracker.ai's unlabeled-video adaptation is **not** equivalent to a purely
inductive model benchmark. Do not assert comparable statistical generalization
conditions. Never supply test *human annotated* fish identities to any
training, model selection or inference command. A specialist can choose an
inductive-only comparison with separate independent training video for all
methods, but must declare the modified protocol rather than silently calling
the transductive system equivalent.

Use unchanged native video files whenever appropriate. Methods requiring
different camera geometry, near-field, fish count or thermal/GPU settings
can be run only on supported domains; record scope restrictions and
failures rather than selecting only successful recordings.

### Required source files

At benchmark root, save:

1. `recording_splits.csv`, exactly
   `dataset,recording_id,fish_group_id,session_id,source_video_sha256,split,annotation_status`;
   the three values of `split` must be `train`, `val`, `test`.
2. `gt.txt`, manually reviewed fish ID + body box truth, **1-based** source
   `frame,id,x,y,w,h,1` in original unrectified pixels. Distinguish ignored
   or unknown animals; do not silently drop relevant classes.
3. `frames.csv`, `frame,review_status` for **every frame 1..N**,
   including empty fish frames, with `review_status=fully_annotated`.
   A source catalogue describing "manual" annotations alone does not prove
   blinded source independence.
4. `timestamps.csv`, `frame,time_s`, strictly increasing presentation
   times of the same decoded frames in **seconds**. Original frame
   dimensions and true timebase must be independently cross-checked.
5. For every method, a `frame,track_id,x_px,y_px,score` predicted centre
   file, `runtime.json`, `training_provenance.json`, and, if available,
   **native** `boxes_mot` scored boxes. Blank `score` is allowed when
   genuinely absent, not a proxy. Predictions must carry no reference truth.
6. `protocol.json`, specifying all preceding paths, method names,
   source partition `test`, fixed pixel-distance threshold and IoU
   threshold, declared source assistance and reference blindness, and
   exactly one source video SHA-256. `inputs.lock.json` freezes those
   files and settings. Reordering/overwriting them invalidates the lock.
7. For actual YOLO fine-tuning, separately supply `images.csv` with
   `split,source_video_sha256,frame,image_path,label_path,image_sha256,label_sha256`,
   actual nonempty image bytes/YOLO labels, original checkpoint `.pt`.
   Staging copies only `train` and `val` data; test samples are excluded
   from the training YAML. This does not prove absence of near-duplicate
   frames unless externally reviewed.

### Native input normalization

Use `inst/python/aqt_priority_b_adapters.py` with one of
`--format idtrackerai`, `--format sleap`, `--format yolo_mot`,
and explicitly declare `--frame-origin 0` or `1`,
`--expected-frames N` and `--out predictions.csv`.

**idtracker.ai:** the expected input is version 6's
`trajectories_tidy.csv` with
`frame,time,individual,x,y,probability`. Nonfinite positions are
unobserved, not fabricated. The individual-to-positive-ID map and the
original SHA are stored. The identity probability **never** counts toward
AP or detection F1 confidence sweeps. If a specific version has a
different schema, adapt after inspecting its actual source export; do
not silently infer column meanings.

**SLEAP:** expected input is a native predicted SLP file readable by
`sleap_io.load_slp`; `PredictedInstance` must have explicit assigned
`track`. The single exported centre is the mean of model-visible
keypoints. This is not guaranteed to coincide with a human fish-body
box centre. Native instance confidence is stored only when provided, and labelled
**pose_instance_score** rather than conflated with YOLO detector confidence.
Reference GT must distinguish the appropriate anatomical centre convention.

**YOLO:** the original scored MOT must be produced by actual model
inference, with true native fish box dimensions and score, and no
source reference coordinates. It can produce both center-distance
common endpoints and **box IoU** endpoints.

Each adapter records the native source SHA256 and refuses overwriting.

## Metrics and interpretation

**Detection:** common matching at a prespecified Euclidean
`centre_gate_px` yields TP/FP/FN, F1, precision and recall.
Confidence-based 101-point interpolated centre AP is meaningful
**only** for a genuine model score (YOLO detection confidence or SLEAP
pose-instance score, reported under their distinct source semantics). Idtracker's
identity posterior and SLEAP identity confidence cannot be relabelled
as detector confidence. Standard detection **box AP50** is only available
for genuine scored body boxes with anatomically equivalent definitions.
This is 101-point AP at one IoU, **not COCO mAP** across .50:.95.

**Tracking:** original pinned TrackEval metric classes compute
HOTA, DetA/AssA, IDF1 and CLEAR ID switches. The three-system
*common comparison* uses the explicitly reported similarity
`max(0,1-distance_px/(2*centre_gate_px))` (distance
`centre_gate_px` corresponds to HOTA alpha=.50). The resulting
`centre_HOTA` is **not** official MOTChallenge *IoU*-HOTA.
Native-box TrackEval is additionally reported where those actual
boxes exist, and may be incomparable when body/pose conventions
differ. A false ID must not be converted to a match to boost HOTA.

**Identity fragmentation:** gaps of unmatched GT observations,
reacquired predicted IDs and label changes are recorded separately,
with missing or non-annotated GT spans not counted as tracker failure.

**Runtime:** measure entire decode + inference + association +
export on the same identified hardware/device, model runtime and
identical original MP4. The result is still **not comparable** without
independent confirmation each run decoded every evaluated frame.
Do not rank methods based only on user-entered frame counts.
Record the feasibility of each model at the same hardware and
quality settings, and include model training as a separate cost.

**Downstream errors:** paired common-support 2D source pixel
movement is compared to the GT bounding-box *centre* using actual
frame timestamps. Never connect unobserved frames or cross changed
predicted fish IDs. Report supported pair fraction and missingness
alongside supported-subset path-length and speed error, and
school-pair distance errors only on matched contemporaneous fish.
This is **conditional on support**; when tracking is poor, lower
support can make numeric error appear deceptively good.
Separately quantify failure/coverage. These are measured-coordinate
error-propagation checks, not animal-stress inference.

## Evidence tiers and acceptance matrix

| Tier | Status | What it justifies |
|---|---|---|
| Structural schema/unit tests | Implemented | Source integrity, clock checks, import contracts |
| Synthetic 3-tracker metric case | CI gated | Scoring correctness; **not** real tracker accuracy |
| Prior real Oxford/Fraunhofer EfficientDet runs | Previously passed | Existing source-specific real-model evidence |
| idtracker.ai on unchanged held-out MP4 | **Not yet executed in this benchmark** | Requires source footage/config, recorded full-frame outputs |
| SLEAP on unchanged held-out MP4 | **Not yet executed in this benchmark** | Requires trained fish pose model/SLP and actual outputs |
| Fine-tuned YOLO train/val/test, actual test execution | **Not yet executed** | Requires train/val images, fitted weights and withheld test |
| 3-way locked real empirical HOTA/IDF1/AP, runtime | **Not certified** | All methods' actual outputs on the exact same independently reviewed frames |
| Behavioural validity on independent fish with physical scale | **Not certified** | Physical calibration and expert-checked measurement ground truth |

The CI artifact `priority-b-synthetic-only-three-system-software-contract`
contains simulated known truth solely for code qualification.
A later real-data artifact must have original recordings, independently
audited annotation source, SHA locks and no synthetic fixture flags.
A software-only green status must **never** overwrite an empirical
certification status.
